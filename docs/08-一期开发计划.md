# 08 · 一期开发计划（决策定案）

> 2026-11-02 与团队讨论定案。本文件是**功能冻结清单**，开发期间改动需全队同意。

## 0. 已锁定的决策

| 决策项 | 结论 |
|---|---|
| 用户端前端 | **纯 Vue3 H5**（Vite + TS + Pinia + Vue Router + Vant） |
| 机构端前端 | Vue3 + Element Plus + ECharts |
| 后端 | Java 17 + Spring Boot 3.x 模块化单体 + Python AI 微服务（轻量） |
| AI 深度 | **一期轻量**：文本情感 + 量表 + 规则分级；LLM 陪伴对话为可选项。**二期升级多模态**（打 4C/挑战杯，见 `07` §5.1） |
| 模块顺序 | **B 健康档案/产检日历 → C 家属协同 → D 社区公益（轻量）→ A 情绪分级（规则版）** |
| 机构端 | 进一期（看板 + 工单两页） |
| 嵌入式脱机终端 | 远期规划，架构预留 IoT 接入层（见 `03` §7） |

> ⚠️ **必须说在前面的问题**：A（情绪分级）是本项目的核心差异化，却排在开发顺序最后。
> 两个风险：越靠后越容易被砍；答辩故事变弱。缓解措施：
> 1. A 的规则版成本其实很低（一张量表 + 规则代码），**W7 雷打不动**
> 2. 进度告急时的砍单顺序：**D（社区）→ LLM 对话 → 内容库篇数，永远不砍 A**
> 3. 数据库第一期就建好 `mood_log / scale_result / risk_event` 三张表，A 上线零迁移

## 1. 功能范围与验收标准（冻结清单）

### 模块 B：健康档案 + 产检日历（W1–W3）

| 功能 | 内容 | 验收标准 |
|---|---|---|
| 注册登录 | 手机号 + 密码（一期免短信验证码），JWT | 新用户 3 步进入首页 |
| 建档 | 身份 / 末次月经或预产期 / 关注点，3 步引导 | 孕周自动计算正确（含孕晚期、产后边界） |
| 阶段首页 | 孕周卡片 + "今日 3 件事"（产检计划 + 内容库混合） | 每日刷新，断签不清零 |
| 指标记录 | 体重 / 血压 / 血糖 / 胎动 | 单次记录 ≤ 30 秒 |
| 产检日历 | 按孕周模板生成全孕期待办（NT/唐筛/糖耐/大排畸…） | 建档即生成完整计划 |
| 报告上传 | 拍照上传至 MinIO，关联产检项 | 可回看、可删除 |
| 趋势图 | ECharts 折线 + 参考区间底色 | 只展示不判读，页面明确注明 |

### 模块 C：家属协同（W4–W5）

| 功能 | 内容 | 验收标准 |
|---|---|---|
| 家庭绑定 | 妈妈端生成邀请码/链接，家属注册后自动入家庭 | 绑定 ≤ 1 分钟 |
| 任务包 | 按阶段模板生成（如"产后第 1 周"）并分配成员 | 上线 3–5 套模板 |
| 任务完成 | 家属打卡 + 步骤化指引 | 妈妈端实时可见状态 |
| 知识同步 | 同一内容卡片同时推给妈妈和家属 | 家属端有"今日一读" |
| 字段级权限 | 家属默认只见任务与状态摘要 | **看不到情绪记录与量表得分**，需逐项授权 |

### 模块 D：社区 + 公益（W6，轻量）

| 功能 | 内容 | 验收标准 |
|---|---|---|
| 匿名树洞 | 发帖 + 敏感词过滤 + 人工审核队列 | 审核通过后出现在列表 |
| 她驿站 | 合作点位列表页（名称/地址/服务/电话） | 静态数据即可，地图为 P2 |
| 公益申请 | 低收入免费服务申请表单 | 机构端可查看申请 |
| 志愿者展示 | 列表 + 服务范围 | 静态数据 |

> D 的定位是"故事完整度"而非"功能完整度"，全部用最便宜的实现，一周收工。

### 模块 A：情绪风险分级（W7–W8，规则版）

| 功能 | 内容 | 验收标准 |
|---|---|---|
| 情绪打卡 | 表情 5 档 + 一句话 | ≤ 30 秒，允许"今天不想说" |
| EPDS 量表 | 10 题逐题作答，标准计分 | 注明量表版本与计分规则 |
| 规则分级 | 绿/黄/红（规则见 `03` §4.5） | 三态各有结果页与行动按钮 |
| 工单 | 黄/红自动生成 `risk_event` | 机构端待办列表出现 |
| 紧急入口 | 结果页常驻心理援助热线 + 就医引导 | 任何状态均可见 |
| LLM 陪伴（P1） | 时间允许再接，带护栏与降级开关 | 可一键关闭 |

### 机构端（穿插 W5–W8）

| 功能 | 验收标准 |
|---|---|
| 登录 + 角色区分（机构 / 志愿者） | — |
| 用户分层看板 | 绿黄红分布、活跃度、近期筛查完成率 |
| 工单列表 + 状态流转 | 待处理 → 处理中 → 已关闭，带处理记录 |

## 2. 工程结构（monorepo）

```
yuji/
├── frontend-h5/        # Vue3 + Vite + TS + Pinia + Vant（妈妈端/家属端角色切换）

├── backend/            # Spring Boot 3 多 module（划分见 03 §3.1）
├── ai-service/         # Python FastAPI（一期：文本情感 + LLM 陪伴）
├── deploy/             # docker-compose.yml + nginx.conf + 初始化 SQL
└── docs/               # 设计文档（4C 交付物从这里直接长出来）
```

## 7. 测试与质量（W2–W3 已完成）

```bash
cd backend && mvn test                          # JDK 21
mvn -Dmaven.compiler.release=17 test            # 仅有 JDK 17 时
```

现状：**194 个用例（common 11 / auth 25 / profile 96 / family 42 / content 13 / admin 7），行覆盖 93.7%（923/985）、分支覆盖 83.3%（338/406）**，JaCoCo 报告在 `backend/*/target/site/jacoco/index.html`。`JdbcDashboardStatsQuery` 的统计 SQL 不在单测范围（需要真库），由冒烟脚本验证口径。

分层策略（按"跑得快"排序）：

| 层 | 手段 | 覆盖对象 | 特点 |
|---|---|---|---|
| 纯函数 | JUnit 5 | `GestationalCalculator`（25 例，含 13+6/14+0、280/281 天边界） | 毫秒级，无依赖 |
| 服务层 | Mockito 隔离 Mapper | `AuthService` / `ProfileService` / `CheckupService` / `HealthRecordService` / `ReportService` | 只测业务规则与错误码 |
| 存储层 | mock client / 真实临时目录 | `MinioFileStorage`（桶自动创建、异常映射）、`LocalFileStorage`（**目录穿越拦截**）、`StorageConfig`（一行配置切实现） | 不依赖 MinIO 进程，`mvn test` 裸跑 |
| 接口层 | standalone MockMvc | 五个 Controller（参数校验、JSON 契约、错误码映射、multipart 上传、下载响应头） | 不启容器，单例毫秒级 |
| 安全链 | `@WebMvcTest` 切片 | 401 拦截、`/api/auth/**` 放行、伪造 token 拒绝 | 必须真实 `SecurityFilterChain` |
| 集成 | `yuji/smoke.ps1` | 注册→建档→孕周→产检→状态→指标录入→趋势→报告上传/下载/删除→邀请码→加入→默认拒绝→授权→越权拒绝→下发→打卡→一次性码失效→家属趋势→机构看板→妈妈越权读看板→**本周知识命中当前孕周→详情含来源→未知分类 40000**（32 步，三账号） | 需要 MySQL，交付前必跑 |

测试写完后被逼出来的真实修复（答辩可讲"测试驱动发现问题"）：

1. `updateStatus(null)` 触发 `List.of(...).contains(null)` 的 NPE，接口返回 50000 而非 40000 —— 已补判空 + 回归用例
2. Spring 6.1 缺 `-parameters` 编译参数，`@PathVariable Long id` 直接 500 —— 已在父 POM 固化
3. JDBC URL 写 `characterEncoding=utf8mb4`（Java 侧应为 `UTF-8`）导致启动即失败 —— 已修正
4. W3：测试基建缺 `ResourceHttpMessageConverter`，下载接口在 standalone MockMvc 下返回 JSON 错误 —— 已在 `MvcTestSupport` 补齐（生产环境不受影响，但暴露了"测试环境与真实环境不一致"的坑）

W3 新增的安全用例（越权与上传攻击面）：

- 报告下载/删除必须校验 `userId` 归属，越权一律 40400（不泄露"文件是否存在"）
- 上传扩展名由 `contentType` 推导，用户把 `shell.jsp` 改名成 `.png` 也只会落成 `.png`
- 本地存储对 `objectKey` 做 `root.startsWith` 校验，`../` 无法逃出上传根目录
- 指标录入用枚举集中管理范围与参考区间，**血压强制收缩压 > 舒张压**，历史脏数据不会让列表 500

纪律建议：每个模块提交必须带测试；CI 里把 `mvn test` 设为合并门禁，覆盖率不得低于 85%。

## 8. 下一步

W1–W5 已交付，**模块 C 完结**：登录/建档/孕周/产检日历/指标记录/报告上传/家属绑定/任务包/字段级授权/家属端趋势图/知识按孕周推送/机构端登录与看板，端到端 **32 步**冒烟通过（三账号：妈妈、家属、机构）。

本轮 W5 的三件事：
1. **知识按孕周推送** —— 新增 `yuji-content` 模块与 `article` 表（V10/V11，14 篇种子）：用 `min_week/max_week` 区间决定谁在什么时候看到什么，排序用"区间中点离当前孕周的距离"；每篇必须带 `source` 与 `reviewer`，详情返回 `disclaimer`。前端在首页给 2 篇「本周知识」，另有知识列表（推荐 / 分类）与详情页
2. **家属端趋势图** —— 抽出 `useTrendChart`，与妈妈端「记录」页共用同一份图表配置（血压双线、参考区间底色、免责声明），避免两边各维护一套；家属只看得到已授权指标的趋势
3. **机构端登录 + 看板** —— 新增 `yuji-admin` 模块与 V9 机构账号（`org001 / org123456`，上线前必须改），登录复用 JWT 并按 `role` 校验；看板只查聚合数（人数、条数、完成率、孕周分桶、近 7 天记录），统计 SQL 集中在 `JdbcDashboardStatsQuery` 便于核对口径

下一步可选方向（按优先级）：
1. **W7 情绪主线**：情绪打卡 + EPDS 量表 + 规则分级 + 机构工单（项目最核心的验收点，AI 微服务在此接入）
2. **W6 轻量模块 D**：树洞 / 驿站 / 公益申请
3. 工程债：被移除成员目前物理删除（可重新用新邀请码加入）；若要"移除黑名单"改软删 + 唯一键调整；机构端 Element Plus 全量引入导致首屏 chunk 偏大，可改按需引入；知识内容目前是 SQL 种子，后续可加机构端 CMS 编辑
