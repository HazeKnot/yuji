# 06 · 落地路线图（约 14 周）

## 1. 总体节奏

```
W1–W2   验证期：访谈 + 竞品 + 定选题（与开发首两周并行，由不同人执行）
W1–W8   建造期：一期开发（按 08 的 8 周计划，模块顺序 B→C→D→A）
W9–W11  试点期：机构合作 + 真实用户 + 数据
W12–W14 打磨期：BP + PPT + 路演 + 答辩演练
```

> 开发与验证**并行**是关键：写代码的人不要停下来做访谈，做访谈的人不要等 Demo。

---

## 2. 分阶段任务

### 阶段一｜验证（第 1–2 周，与开发并行）
| 任务 | 产出 | 负责人 |
|---|---|---|
| 深访 10 位孕产期女性（孕期/产后各 5） | 访谈纪要 + 20 条原话引用 | 产品 |
| 访谈 2 位产科/妇幼医生、1 位心理咨询师 | 专业意见 + 潜在顾问 | 商务 |
| 竞品拆解 5 款（注册体验 + 截图） | 竞品对比表 | 设计 |
| 政策与数据检索（标源） | 政策清单 + 数据表 | 文案 |
| 确认项目名与 slogan | 品牌一页纸 | 全员 |

**验收**：能说出 3 类痛点，每类都有 2 条以上真实用户原话。

### 阶段三｜试点（第 9–11 周）
| 任务 | 产出 | 负责人 |
|---|---|---|
| 谈 1 家妇幼机构 / 1 家月子中心 | 合作意向书（盖章或书面确认） | 商务 |

**验收**：有真实用户数据 + 至少 1 份合作意向 + 1 个可公开讲述的用户故事。

## 3. 团队分工建议（5 人配置）

| 角色 | 核心职责 | 关键能力 |
|---|---|---|
| 项目负责人 | 统筹、路演主讲、对外合作 | 表达、项目管理 |
| 产品/设计 | 需求、原型、视觉、Demo 体验 | Figma、用户研究 |
| 技术 | Vue3 前端 + Spring Boot 后端 + AI 接入 | 全栈 |
| 内容/医学联络 | 内容库、顾问对接、合规文本 | 写作、医学常识 |
| 运营/商务 | 机构 BD、社群、试点执行、数据 | 沟通、执行力 |

> 若只有 3 人：负责人兼商务，技术兼产品，内容兼运营。
> **千万别 5 个人都写 BP 没人写代码。**

## 4. 里程碑与 KPI

| 时间 | 里程碑 | KPI |
|---|---|---|
| W2 | 完成验证 | 10 份访谈、5 款竞品、3 类痛点 |
| W3 | 模块 B 可用 | 建档→产检日历全流程 |
| W5 | 模块 C 可用 | 家属绑定→任务闭环 |
| W8 | **一期交付** | 全链路跑通、一键部署、演示数据 |
| W11 | 试点启动 | 1 家机构、50+ 注册、5 位志愿者 |
| W14 | 材料完备 | BP + PPT + 视频 + Q&A 手册 |

---

## 5. 每周固定动作（避免拖延）

- **周一 30 分钟站会**：上周完成 / 本周计划 / 卡点
- **周三 用户时刻**：轮流分享一条用户原话或一个新发现
- **周五 演示日**：必须拿出"能看的东西"，不接受"还在做"
- **每两周一次外部反馈**：找指导老师或陌生同学听 5 分钟路演

---

## 6. 常见翻车点

| 翻车点 | 预防 |
|---|---|
| 前 6 周都在写文档，没写代码 | 第 1 周必须开始动手，Demo 优先于 BP |
| 功能越加越多，最后啥都不深 | 守住 `08` 的冻结清单，砍功能是常态 |
| **模块 A（情绪分级）被挤掉** | 砍单顺序：D → LLM 对话 → 内容篇数，**永不砍 A** |
| 数据全靠编 | 每个数字标来源；编造一旦被追问即出局 |
| 只讲情怀没有落地 | 情怀开场，数据收尾 |
| 忽视合规 | 第 6 周前完成隐私政策与红线自查 |
| 路演超时 | 从第一次排练就用计时器 |
| 单点依赖某个人 | 关键材料双人备份，主讲准备 B 角 |
