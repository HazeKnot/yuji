# 10 · 运行方式（本地演示环境）

> 本文档描述「育己」平台在一台 Windows 机器上完整跑起来的方式：环境要求、启动顺序、演示账号、验证清单与常见问题。
> 适用于当前演示机（JDK/MySQL 已就绪，脚本在 `c:\desktop\20261102201632` 根目录）。

---

## 1. 服务与端口一览

| 服务 | 技术 | 端口 | 地址 | 说明 |
|---|---|---|---|---|
| MySQL | MySQL 8 | 3306 | `localhost:3306/yuji` | 库名 `yuji`，Flyway 自动建表 |
| 后端 API | Spring Boot 3 / JDK 21 | 8080 | http://localhost:8080 | JWT 鉴权，健康检查 `/actuator/health` |
| AI 微服务 | Python FastAPI | 8000 | http://localhost:8000 | 情绪分级 / 咨询共情 / **社区风控扫描** |
| 用户端 H5 | Vue3 + Vant | 5173 | http://localhost:5173 | 妈妈 / 家属使用，`/api` 代理到 8080 |
| 机构端 | Vue3 + Element Plus | 5174 | http://localhost:5174 | 机构租户工作台，`/api` 代理到 8080 |

后端与前端是**必须**的；AI 微服务可选（不可用时自动降级：咨询走本地知识卡，风控走本地词典）。

## 4. 启动（顺序：MySQL → 后端 → AI → 前端）

> 每个脚本都会把日志重定向到根目录，脚本窗口不要关，关掉即停服务。

**① 确认 MySQL 已启动**（Windows 服务或 `net start mysql`），然后：

**② 后端**

```cmd
cd /d c:\desktop\20261102201632
start "" start-backend.cmd
```

- 实际执行：`jdk-21.0.13+9\bin\java.exe -jar yuji-server-0.1.0-SNAPSHOT.jar`，日志 `backend-run.log`
- 就绪判断：`curl http://localhost:8080/actuator/health` 返回 `{"status":"UP"}`
- 首次启动会跑迁移，约 20–40 秒

**③ AI 微服务（可选但建议开）**

```cmd
start "" start-ai.cmd
```

- 实际执行：`python -m uvicorn main:app --host 0.0.0.0 --port 8000`，日志 `ai-service.log`
- 就绪判断：`curl http://localhost:8000/health` 返回 `{"status":"ok"}`

**④ 用户端 + 机构端**

```cmd
start "" start-h5.cmd
start "" start-admin.cmd
```

- H5：http://localhost:5173 ，机构端：http://localhost:5174
- 若改过代码需要重启，直接关掉对应窗口重跑脚本即可（Vite 已开热更新）

**⑤ 灌演示数据（可选，幂等）**

```cmd
cd /d c:\desktop\20261102201632\yuji
node demo-seed.mjs
```

产出：妈妈「小满」孕 28 周 + 体重/血压/血糖/胎动记录、2 个产检已完成、家属「阿哲」已绑定并授权可见体重/血压、任务包已下发。

## 6. 验证清单（跑完建议逐项点一遍）

**接口侧**

```cmd
curl http://localhost:8080/actuator/health
curl http://localhost:8000/health

:: 登录拿 token
curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d "{\"phone\":\"13800000001\",\"password\":\"demo123456\"}"

:: AI 风控扫描（直接看定级结果）
curl -X POST http://localhost:8000/api/v1/moderate/scan -H "Content-Type: application/json" -d "{\"text\":\"最近天天哭，感觉撑不住了\",\"context\":\"checkin\"}"
```

`/api/v1/moderate/scan` 返回四种级别：

| level | 触发 | 内容 | 告警 |
|---|---|---|---|
| `ALERT` | 危机表达（不想活/自残…） | 帖子进待审核 | 红档工单，24h 内联系 |
| `BLOCK` | 导流违规（加微信/代购/药流…） | 帖子/评论被拦 | 无（内容风控） |
| `WATCH` | ≥2 个消极词 | 正常发布 | 黄档预警（消极人选筛查） |
| `NONE` | 干净 | 正常发布 | 无 |

**页面侧（演示动线）**

1. H5 登录妈妈账号 → 首页孕周卡片、产检日历、指标趋势
2. H5 → 她社区：发一条含「不想活」的帖子 → 提示审核中
3. H5 → 心理：情绪打卡填「天天哭，撑不住了」提交
4. 机构端登录 → 「用户管理」看到该会员与风险分级摘要
5. 机构端 → 「AI 风控告警」看到红档（社区）+ 黄档（打卡）各一条，点「跟进」流转状态
6. 机构端 → 「预约线索」只有本机构数据（租户隔离）

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `mvn package` 报 `Unable to rename ...jar` | 旧 jar 被运行中的进程占用。先 `taskkill /f /im java.exe` 再打包 |
| 后端启动报 `UnsupportedClassVersionError` | 用了系统 Java 17。显式用 `jdk-21.0.13+9\bin\java.exe` |
| 机构端提示「手机号格式不符合要求」 | 那是注册接口的校验；机构请用 `13900000001` 或走 H5「机构登录」入口（只要求 ≥4 位账号） |
| 机构端登录后 403「账号未绑定机构」 | 该账号 `user.org_id` 为空，执行 `UPDATE user SET org_id=1 WHERE phone='xxx';` |
| 机构端看不到会员 | 会员 = 有 `partner_lead` 且 `user_id` 非空的用户。可用 H5 向该机构提交一次预约意向 |
| 社区帖子一直「审核中」 | 命中了风控（危机/导流词），机构端「社区审核」可放行 |
| AI 服务没起 | 不影响主流程：咨询降级为知识卡文案，风控降级为本地词典，级别判定一致 |
| 端口被占 | `netstat -ano \| findstr :8080` 查 PID，再 `taskkill /pid <PID> /f` |
| 前端 502 / 接口不通 | 后端没起或没就绪，看 `backend-run.log` 尾部 |

**停止服务**

```cmd
taskkill /f /im java.exe        :: 后端
taskkill /f /im node.exe        :: 两个前端（会一起停，按需）
taskkill /f /im python.exe      :: AI 服务
```

**改代码后的重启动作**

- 前端：Vite 热更新，改完刷新页面即可
- 后端：停进程 → `cd backend && mvn -DskipTests package` → 重跑 `start-backend.cmd`
- AI：改 `main.py` 后必须重启 uvicorn（未开 `--reload`）
