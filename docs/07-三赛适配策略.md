# 07 · 三赛适配策略（挑战杯 / 互联网+ / 计算机设计大赛）

> 核心结论：**一个作品内核，三种讲法，三套材料。**
> 不要做三个项目，也不要用同一份 PPT 投三个比赛——三者的评委关心的东西几乎不重叠。

---

## 1. 三个比赛到底在评什么

| 维度 | 计算机设计大赛（4C） | 挑战杯 | 互联网+（中国国际大学生创新大赛） |
|---|---|---|---|
| 本质 | **作品赛** | **竞赛作品 / 创业计划赛** | **创业赛** |
| 评委最想看到 | 东西做出来了、技术有含量、演示流畅 | 研究扎实 / 商业闭环 + 落地证据 | 能不能成生意、团队能不能干、社会价值 |
| 一句话 | "你写出来了什么？" | "你证明了什么？" | "你能赚到钱吗？" |
| 商业模式 | **不重要，甚至反感** | 小挑必须，大挑不需要 | **最重要** |
| 技术深度 | **最重要** | 中（大挑重） | 低（够用即可） |
| 数据/实证 | 系统指标、实验对比 | **问卷 N≥300、统计检验、查新** | 用户数、收入、合作方 |
| 材料重心 | 演示视频 + 设计文档 + 源码 | 研究报告 / 商业计划书 | BP + 路演 + 财务模型 |
| 现场 | 演示 + 技术追问 | 陈述 + 深度质询 | 5+3 分钟路演 + 答辩 |
| 致命伤 | Demo 跑不起来 | 数据造假、无创新点 | 没有落地、财务拍脑袋 |

**由此推出的战略**：
- 用 **4C 逼出技术真货**（这是作品的骨头，另外两个比赛都靠它撑）
- 用 **挑战杯逼出实证数据**（问卷、访谈、模型验证，这是学术信用）
- 用 **互联网+ 逼出落地证据**（合作机构、真实用户、现金流设计，这是可信度）

三者互为证据链，形成一个"越打越强"的正循环。

## 2. 一套内核，三种叙事

同一个技术点，三个比赛要讲成三个故事。**这是本策略最关键的一张表**：

| 技术内核 | 4C 讲法（技术） | 挑战杯讲法（研究） | 互联网+ 讲法（商业） |
|---|---|---|---|
| 情绪风险分级引擎 | 多模态特征融合 + 可解释分级算法，准确率/召回率/AUC 对比实验 | 孕产期心理风险分级模型的构建与效度检验（N=xxx，信效度分析） | 把基层产后抑郁漏筛率从极低水平提升到可测量的覆盖率 |
| 家属协同端 | 多端状态同步 + 权限模型 + 消息触达机制 | 家庭协作对产妇心理状态影响的干预实验（前后测对照） | 提升留存与付费转化的产品结构，LTV/CAC 改善 |
| AI 陪伴对话 | LLM + RAG + 三层安全护栏的工程实现 | 生成式 AI 在孕产健康科普中的适用边界与风险控制 | 用 AI 替代高成本人工，跑通单位经济模型 |
| 公益下沉 | 低带宽/低配置适配、离线缓存 | 县域妇幼健康服务可及性研究 | 社会价值 + 政府购买 / 基金会的可持续现金流 |

> 记忆法：**4C 说"怎么做的"，挑战杯说"证明了什么"，互联网+说"值多少钱"。**

## 3. 三套命名

| 比赛 | 作品名 | 为什么这样起 |
|---|---|---|
| 计算机设计大赛 | 《基于多模态情绪感知的孕产期心理健康分级预警系统》 | 技术词前置，一眼看出用了什么方法 |
| 挑战杯 | 《孕产期女性心理健康风险分级模型的构建与家庭协同干预实证研究》 | 学术句式，"构建""实证"是关键词 |
| 互联网+ | 《育己——以母亲为主体的孕产期健康支持平台》 | 品牌 + 定位，路演好记 |

**注意**：作品名不同但内核必须一致，答辩时被问"这是同一个项目吗"要坦然回答"是同一套系统，按不同赛道要求做了不同侧重"，这是正常且被允许的。

## 4. 赛道 / 组别选择建议

### 计算机设计大赛（4C）
| 选项 | 说明 | 建议 |
|---|---|---|
| **软件应用与开发** | 最稳，重完整度与工程性 | ✅ 主选 |
| 人工智能应用 | 天花板更高，需突出算法与实验 | ✅ 若团队有算法能力则选这个 |
| 物联网应用 | 需硬件 | ❌ 不建议 |

4C 硬性材料通常包括：**作品演示视频、设计文档、安装部署说明、源代码、答辩 PPT**，且有严格格式与时长限制（以当年章程为准）。**演示视频是第一道生死线**，很多队伍死在这里。

### 挑战杯
- **偶数年偏"创业计划竞赛"（小挑）**，**奇数年偏"课外学术科技作品竞赛"（大挑）**——具体届次与年份以官方通知为准。
- 小挑组别建议：**社会治理和公共服务**（本项目的天然归属）
- 大挑组别建议：**科技发明制作 B 类**（软件类，投入较小、非生产性）
- 若走大挑，务必准备：**查新报告**（教育部科技查新工作站）、**软件著作权**、**问卷原始数据与统计过程**

### 互联网+
| 赛道 | 适配度 | 条件 |
|---|---|---|
| 高教主赛道 · 本科生创意组 | ✅ 首选 | 未注册公司、有创意与原型即可 |
| 高教主赛道 · 初创组 | 中 | 需注册公司 + 实际运营 |
| 红旅赛道 · 公益组 | ✅ 强适配 | **必须有真实乡村/县域落地**，否则别碰 |
| 产业命题赛道 | 低 | 需企业命题对接 |

> 建议路径：**本科生创意组** 起手，有县域落地后再补 **红旅公益组**（同一作品不同组别，注意章程对重复参赛的限制）。

## 5. 技术护城河升级（为 4C，也顺带养另外两个）

现在的方案技术含量偏"应用层"，在 4C 容易被评为"就是个调用 API 的 App"。必须往算法层扎一层。**四条可行且学生做得出来的路线**：

### 5.1 多模态情绪识别（技术主攻方向）
```
输入：打卡文本 + 语音片段 + 量表作答 + 行为日志（打卡时间/频次/连续低落天数）
  ├─ 文本：中文预训练模型（BERT-wwm / RoBERTa-wwm）微调 → 情绪概率
  ├─ 语音：openSMILE 提取 eGeMAPS 声学特征 → XGBoost / SVM 分类
  ├─ 量表：EPDS/GAD-7 结构化特征
  └─ 行为：时序特征（滑动窗口统计）
融合：晚期融合（加权/Stacking）→ 风险概率 → 三级映射
```
- 公开数据集打底（如 RAVDESS、CASIA 等语音情感集），自采小样本做域适配
- **必须做对比实验**：单模态 vs 多模态、不同融合策略、消融实验——这是 4C 评委最看重的"科研感"
- 评价指标：Accuracy / Precision / Recall / F1 / AUC，并说明**为什么召回率比准确率重要**（漏筛代价更高）——这句话能直接打动评委

### 5.2 可解释性
- 输出"为什么判为黄档"：哪些特征贡献最大（SHAP / 注意力权重可视化）
- 对用户展示的可解释文案 + 对医生展示的特征贡献图
- **可解释 = 合规 + 专业 + 技术亮点，一箭三雕**

### 5.3 隐私保护（4C 的硬核加分项）
- 端侧推理：模型蒸馏/量化后用 TFLite / Paddle Lite 部署到小程序端，**数据不出端**
- 或模拟联邦学习（FedAvg）流程，说明"多家机构数据不共享也能联合建模"
- 这一条在健康数据场景下极其讨喜，且能同时满足挑战杯"先进性"和互联网+"合规壁垒"

### 5.4 适老化与低配置适配
- 大字号模式、语音交互、弱网/离线缓存
- 面向县域与长辈用户，**体现社会关怀的同时是真实工程难点**

> 优先级建议：**5.1 多模态融合 > 5.2 可解释 > 5.3 隐私 > 5.4 适老化**。
> 5.1 是骨架，其余是血肉。别四条都浅尝，做出 5.1 的完整实验就够拿省一。

## 6. 三赛各自的"必须具备"

### 打 4C 之前必须有
- [ ] 可现场跑的完整 Demo（不依赖网络的部分要能离线跑）
- [ ] 演示视频（严格控时长，画质清晰，有字幕）
- [ ] 设计文档（需求→设计→实现→测试，含架构图、ER 图、核心算法流程图）
- [ ] 实验对比表（我们 vs 基线，有数字）
- [ ] 源代码 + 部署说明（评委可能现场要求跑）
- [ ] 软著受理号（早申请，2–4 个月下证）

### 打挑战杯之前必须有
- [ ] 问卷 N ≥ 300（线上+线下），有样本结构说明与统计检验
- [ ] 10–20 份深度访谈原始记录（脱敏）
- [ ] 查新报告
- [ ] 研究报告（按学术论文体例：摘要/文献综述/方法/结果/讨论/结论）
- [ ] 指导老师（建议副高以上）+ 医学/心理顾问
- [ ] 干预前后测数据（哪怕小样本 30 人，有对照就很强）

### 打互联网+之前必须有
- [ ] 团队 8–15 人、跨学科（技术/医学/设计/商科/运营）
- [ ] 三年财务预测（收入/成本/现金流，含假设说明）
- [ ] 落地证据：合作意向书 ≥ 2 份、真实用户数、社群规模
- [ ] 股权/分工结构（创意组可简化）
- [ ] 社会价值量化（公益名额、县域覆盖、志愿者时长）
- [ ] 5 分钟路演稿 + 3 分钟问答弹药库

## 7. 时间错位与复用路线

三个比赛赛程错开，同一作品可以一年打三个，逐年迭代升级。

| 时间 | 主攻 | 该阶段产出的"可复用资产" |
|---|---|---|
| 11 月–次年 1 月 | 打磨作品 | 完整 Demo、软著申请、问卷设计与发放 |
| 2 月–3 月 | **4C 报名与省赛** | 演示视频、设计文档、实验报告 |
| 4 月–6 月 | **互联网+ 校赛/省赛** | BP、财务模型、合作意向、路演稿 |
| 6 月–8 月 | **4C 国赛 + 互联网+ 省赛** | 答辩弹药库、技术追问应答 |
| 9 月–11 月 | **挑战杯**（按当年届次） | 研究报告、查新、实证数据 |
| 次年 | 用今年拿到的奖项与数据，升级作品再打一轮 | 论文、专利、更大规模试点 |

> 关键节奏：**春季主攻 4C（技术），初夏主攻互联网+（商业），秋季主攻挑战杯（学术）**。
> 三者产出的资产互相喂养，不是三份重复劳动。

## 8. 复用合规提醒（别踩坑）

1. **已获省级以上奖项的作品**，多数赛事对重复参赛有限制（如互联网+曾规定获国赛金奖项目不得重复参赛）。同一作品跨赛事使用通常允许，但**同一赛事内不得重复报**。
2. 提交前务必读当年**官方章程**中关于"作品原创性""往届获奖作品""跨赛道报名"的条款，并保留截图存档。
3. 三个比赛的作品名、团队排序可以不同，但**核心技术必须是你自己的**，不得一稿多买。
4. 涉及医学内容，所有对外材料需经顾问审核，避免出现诊疗承诺。

## 9. 团队配置（跨三赛的最小可行阵容）

| 角色 | 人数 | 主要服务赛事 | 关键能力 |
|---|---|---|---|
| 队长/主讲 | 1 | 三赛通吃 | 表达、统筹 |
| 算法 | 1–2 | **4C 主力** | 机器学习、实验设计 |
| 全栈 | 1–2 | 4C 主力 | 小程序 + 后端 |
| 设计 | 1 | 4C + 互联网+ | UI/视频剪辑 |
| 商科/运营 | 1–2 | **互联网+ 主力** | 财务、BD、路演 |
| 医学/心理顾问 | 1–2（老师/研究生） | 挑战杯 + 合规 | 量表、伦理、审核 |

> 铁律：**算法位不能空。** 没有算法，4C 只能拿"完整度分"，拿不到"创新分"；挑战杯也写不出"先进性"。

## 11. 本周就能做的三件事

1. **查清三个比赛当年章程**（4C 分类与材料格式、互联网+ 赛道与组别、挑战杯当年届次与组别），把截止日倒排进 `06-90天路线图.md`。
2. **确定 4C 分类**（软件应用与开发 / 人工智能应用），这决定技术文档的写法。
3. **找算法同学**——这是当前最大短板，先解决人，再解决技术。
