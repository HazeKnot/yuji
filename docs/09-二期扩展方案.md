# 09 · 二期扩展方案：从孕产工具到女性全周期健康与机构协作平台

> 版本 v0.3 ｜ 2026-11-04
> 对应代码：`yuji/backend/yuji-wellness`、H5 新增页面、机构端新增四个工作台
> 对应迁移：`V12` – `V18`

---

## 1. 为什么扩展

一期解决的是"孕期到产后 6 个月"这一段最密集的需求，但它天然有三处天花板：

1. **用户生命周期太短**：孕产是一次性事件，用户平均只活跃 12–18 个月，获客成本摊不薄。
2. **真实需求更早、更长期**：痛经、月经不调、分泌物异常、乳房胀痛、漏尿、避孕选择、更年期潮热——这些困扰往往在怀孕之前就已存在，且更"难以启齿"。
3. **B 端只买了"看板"**：妇幼保健院和月子中心真正缺的是**筛查后的转介链路**与**可跟进的预约线索**，不是又一个数据大屏。

所以二期的方向不是"多加几个页面"，而是把产品从**孕产记录工具**升级为**女性全周期健康入口 + 机构协作网络**：

> 从"怀孕了才打开"变成"每个月都用得上"，从"记录数据"变成"帮助她决定下一步"。

---

## 2. 新定位

**一句话**：育己是一个以女性为主体的全周期健康与育儿支持平台——从经期到更年期，从身体困扰到情绪康复，从线上自助到线下机构转介。

**三条产品原则**

1. **不诊断，但不敷衍**：私密咨询不做"AI 医生"，而是把"可以先做什么、什么时候必须就医、挂哪个科、去之前准备什么"讲清楚。
2. **不制造焦虑，也不假装轻松**：痛经不必硬扛，漏尿不必羞耻，产后情绪不是矫情；但所有提示都要配"下一步怎么做"。
3. **不把女性健康做成流量生意**：合作机构只做信息展示与预约线索，不按诊疗收入排名，不向机构开放个人健康明细。

## 3. 用户端功能地图

| 频道 | 解决什么 | 关键设计 |
|---|---|---|
| 首页 | 今天该做什么 | 阶段自适应：经期 / 备孕 / 孕期 / 产后 / 育儿 / 更年期，一屏只给一个主指标 |
| 健康 | 身体与私密 | 周期预测、月事餐饮、私密咨询、指标、报告、产检、家人协同 |
| 社区 | 经验与羞耻感 | 五类分区 + 匿名发帖 + 危机词转人工审核 |
| 关怀 | 月子、育儿、心理 | 42 天月子清单、按月龄课程、情绪打卡与 EPDS |
| 我的 | 身份与隐私 | 阶段可改、家属权限入口、数据边界说明 |

### 3.1 全周期档案：不强迫所有人填孕产信息

一期 `profile` 表以末次月经/预产期为核心，这对经期用户是硬门槛。二期新增 `wellness_profile`，与孕产档案**按 user_id 并存**：

- 经期/备孕/更年期用户：只填最近一次月经、平均周期与经期长度；
- 产后者：填分娩日期、分娩方式、宝宝生日；
- 孕期用户：继续走一期 `profile`，首页自动识别孕周。

首页以"至少有一份档案"为可用条件，避免把非孕用户挡在门外；营养、周期、育儿内容都由 `life_stage` 决定，而不是由孕周决定。

### 3.2 私密健康咨询：知识卡驱动的分诊，而不是聊天机器人

针对"难以启齿的女性疾病"，产品做了刻意的取舍：

- **入口匿名**：不需要真名，会话不出现在社区，家属端没有授权入口；
- **9 张审核过的主题知识卡**：分泌物异常、外阴瘙痒、月经不规律、痛经、乳房硬块、盆底/漏尿、避孕选择、HPV/TCT 报告、更年期；
- **回答结构固定**：可以这样理解 → 可以先做 → 必须尽快就医的信号 → 日常护理 → 建议科室 → 内容来源；
- **风险词即时升级**：出现大出血、晕厥、剧烈腹痛、胸痛、绝经后出血等，直接提示尽快就医并把会话标为红档；
- **一键转介**：生成风险工单，推荐附近合作机构，并留下"就诊准备卡"（症状持续时间、伴随症状、已尝试的处理）。

AI 微服务只负责"把开场话说得有温度"，医学内容始终来自审核过的知识卡；服务不可用时整条链路照常工作（Java 侧 800ms 连接超时 + 1.5s 读取超时，失败即降级）。

### 3.3 月事餐饮规划：把"多喝热水"变成一周可执行的菜

- 按周期四阶段（经期 / 卵泡期 / 排卵期 / 黄体期）匹配 28 套日模板；
- 每天早餐、午餐、晚餐、加餐 + 营养重点 + 一句话搭配提示；
- 自动汇总本周购物清单，减少"知道该吃却不知道买什么"的摩擦；
- 没有周期记录时退化为一套均衡食谱，并明确告诉用户"记录后会切换"；
- 贫血、妊娠糖尿病、食物过敏等场景明确提示以医生/营养师方案为准。

### 3.4 她社区：匿名是功能，不是漏洞

- 五个分区：经验分享、难言之隐、月子日记、育儿互助、心理树洞；
- 发帖可选匿名，**服务端不把 user_id 返回给前端**，昵称落库快照、匿名帖渲染为"匿名姐妹"；
- 命中自伤/危机词或导流词（加微信、代购、药流等）自动进入 `PENDING`，机构端人工复核；
- 点赞用唯一键防重复，评论计数落库，列表分页稳定。

### 3.5 月子调理：42 天任务清单，而不是又一篇文章

- 输入分娩日期与分娩方式，按产后天数生成任务：饮食、伤口/恶露观察、喂养、盆底唤醒、情绪打卡、避孕、42 天复查；
- 今日任务 + 接下来 + 42 天全清单三层结构，完成率可视化；
- 所有任务都是**照护提醒**，不根据症状生成新的医疗处置；
- 出现发热、出血增多、伤口异常、情绪持续低落时，提示就医而不是继续打卡。

### 3.6 育儿教育：按月龄命中，5 分钟能看完

- 6 门课程覆盖 0–3 月护理、母乳喂养、睡眠、辅食、语言情绪、如厕训练；
- 课程带适用月龄、来源与审核方，正文引用《中国居民膳食指南（2022）》《0–5 岁儿童睡眠卫生指南》等；
- 没有宝宝生日时提示补充，而不是推一堆无关课程；
- 每条课程都带"出现哪些情况需要就医"的边界。

### 3.7 产后心理康复：EPDS 分级 + 工单，不做诊断

- 30 秒情绪打卡：1–5 分 + 情绪标签 + 一句话；
- EPDS 10 题，0–3 分计分：0–9 绿档、10–12 黄档、≥13 红档；**第 10 题只要 >0 直接红档**；
- 黄档自动生成陪伴工单，红档提示尽快面对面评估并给出心理援助热线；
- 结果页只写"风险分层 + 建议"，不出现"你得了抑郁症"；
- 机构端只看到风险摘要与分级，不展示聊天全文。

### 3.8 合作机构：把线上需求接到线下

- 用户端按类型筛选妇幼保健院、月子中心、产后康复、社区机构；
- 机构详情展示服务包、地址与价格说明；
- 预约只提交称呼、手机号、需求与期望日期，**不上传健康档案**；
- 机构端可维护机构与服务包、跟进线索状态（待联系 / 已联系 / 已预约 / 已关闭）。

## 4. B 端商业设计

### 4.1 两类合作方，三种付费点

| 合作方 | 他们缺什么 | 平台提供 | 付费点 |
|---|---|---|---|
| 妇幼保健院 / 社区机构 | 筛查后的随访人力、健康教育内容、产后复查到诊率 | 内容共建、风险工单、复查提醒、预约线索 | 年度 SaaS 服务费 / 内容共建费 |
| 月子中心 / 产后康复 | 可信获客、服务标准化展示、用户信任 | 机构主页、服务包展示、预约线索、育儿课程联名 | 入驻年费 + 线索服务费（不按诊疗分成） |
| 企业工会 / 保险 | 女性员工健康福利、理赔后的康复支持 | 企业专属频道、匿名咨询、团体筛查报告（脱敏聚合） | 员工福利采购 |

**明确不做**：不做在线问诊、不卖药、不做医疗效果承诺、不按诊疗收入抽成、不向机构开放个人健康明细。

### 4.2 单位经济（可验证的假设，不虚构数据）

- 收入侧：机构入驻年费（中小机构 0.8–3 万/年）+ 线索服务费（按有效到店结算）+ 内容共建项目费；
- 成本侧：内容审核与医学顾问（按篇/按月）、咨询师/志愿者跟进（按工单）、云与存储；
- 关键指标：机构续费率、有效线索到店率、黄档工单 48 小时响应率、红档 24 小时转介率、次月留存。

> BP 里只写"假设 + 验证方式"，不写没有来源的市场规模数字。真实合作意向书比预测表更有说服力。

### 4.3 与一期的关系

一期已经具备的 `auth / profile / family / content / admin` 全部复用：

- 登录与 JWT 不分端，机构端继续用 `org_token`；
- 孕产档案、产检、指标、报告、家属协同不改表；
- 内容库继续按孕周推送，新增课程与知识卡单独建表；
- 机构端从"一个看板"扩展为五个工作台，但依然只给聚合数据与用户主动提交的线索。

## 6. 合规与安全边界

1. **不做诊断、不开处方、不做影像判读**：所有结果页都带 `disclaimer`；
2. **数据最小化**：机构只看到用户主动提交的预约信息与风险摘要，看不到周期、情绪、聊天全文；
3. **匿名权**：私密咨询与社区匿名帖不向家属端开放；
4. **危机处置**：EPDS 第 10 题阳性、咨询风险词、社区危机帖都会触发人工/转介路径，而不是只弹一句提示；
5. **内容可溯源**：知识卡与课程保留 `source`、`reviewer`，机构端审核留痕；
6. **资质边界**：量表是筛查工具，咨询是健康教育；需要诊疗时明确建议线下就医；
7. **数据安全**：健康数据加密传输、按角色鉴权、越权一律 404/403，不在日志中打印敏感内容。

> 答辩时主动说"我们不做什么"，比强调"什么都能做"更能建立信任。

## 7. 5 分钟演示脚本

1. **新用户**：选择"经期管理" → 填最近一次月经 → 首页显示"周期第 X 天"，而不是强制填孕周。
2. **月事餐饮**：进入"月事餐饮"，展示按阶段生成的一周食谱与购物清单。
3. **私密咨询**：选"分泌物颜色/气味不对劲" → 输入"反复几个月，有异味，自己买洗液越洗越糟" → 助手给出"可以先做 / 必须就医信号 / 建议科室 / 来源"，并提示不要自行冲洗。
4. **风险升级**：输入"今天突然大出血，头晕" → 会话变红档 → 点击"转人工" → 生成工单并推荐妇幼保健院。
5. **社区**：发一条匿名"难言之隐" → 列表显示"匿名姐妹" → 机构端点开审核。
6. **月子**：切到"关怀 - 月子调理"，填分娩日期 → 今日任务打卡 → 展示 42 天进度。
7. **心理**：情绪打卡 → EPDS 10 题（演示第 10 题阳性）→ 红档结果 + 热线 + 转介机构。
8. **机构端**：登录 `org001 / org123456` → 看板（全周期运营 + 孕产照护）→ 风险跟进 → 合作机构与预约线索。

演示时只讲一条主线：**她说出难以启齿的困扰 → 平台帮她判断下一步 → 需要时接到线下机构**。其余功能作为支撑，不要平均用力。

## 9. 答辩预设问答

**Q：你们是不是在做在线问诊？**
A：不是。我们没有医生坐诊、不开处方、不做诊断。私密咨询做的是健康教育与就诊准备：告诉用户哪些情况可以先观察、哪些必须尽快就医、挂哪个科。需要诊疗时转介到线下合作机构。

**Q：AI 会不会说错？**
A：医学结论不交给模型。结构化建议来自审核过的知识卡，AI 只负责共情开场；模型不可用时整条链路自动降级，不影响使用。

**Q：为什么从孕产扩到全周期，会不会失焦？**
A：孕产仍是最高频、最刚性的场景，但用户的生命周期不应在产后 6 个月结束。我们扩的是同一群女性的前后两端：经期与更年期。数据模型上两套档案并存，不破坏一期体验。

**Q：机构为什么愿意付费？**
A：他们缺的不是又一个看板，而是筛查后的随访链路和可跟进的预约线索。平台提供内容共建、风险工单与到店线索，按年费/线索结算，不参与诊疗分成。

**Q：商业化会不会影响中立性？**
A：机构展示不按诊疗收入排名，用户看到的服务包与价格由机构提供、平台审核；平台不向机构开放个人健康明细，转介也不以佣金为导向。
